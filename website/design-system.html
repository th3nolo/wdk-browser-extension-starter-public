Design reasoning

System principles

The assumptions behind the theme system and approval-focused UI.

01
The wallet is a security surface, not a canvas. Visual changes must never hide, reorder, or soften approval-critical data. Theming only touches presentation tokens — never the meaning of an origin, amount, network, or warning.
02
Everything brand-able routes through one token contract. The UI references only semantic variables (--accent, --surface, --radius, --font-head…). A theme is a small object that fills the contract. Swap it and the whole wallet rebrands; the React components, background controller, and WDK modules never change.
03
Two base directions cover common forks. An Evolved premium-dark direction refines the shipped teal UI, and a Neutral base in light + dark is designed to be recolored from scratch. Six fictional brands demonstrate the range.
04
Eight customization axes are first-class. Color, typography, logo, corner radius & shape, density, light/dark, iconography, and navigation pattern — each is a knob a whitelabeler can turn safely. The prototype exposes all of them as live tweaks.

Foundations · typography

Type roles, not fixed fonts

Three roles — head, body, mono — are swappable per theme. Amounts and addresses always use the mono role with tabular figures so columns line up. Specimen reflects the active theme.

Whitelabel guide

Ship a brand in one object

To rebrand the wallet, a team adds one theme object. No component edits, no backend edits. Here is the full shape — exactly what every theme in this gallery is.

// brand.theme.js — the entire rebrand
export const myBrand = {
  id: "my-brand", name: "My Wallet",
  mode: "dark",            // light | dark
  tint: 255, chroma: 0.014, // neutral hue + saturation
  accent: {
    base: "#2dd4bf", strong: "#14b8a6",
    ink: "#03231f",    // text on accent
  },
  fonts: {
    head: "'Space Grotesk', sans-serif",
    body: "'Hanken Grotesk', sans-serif",
    mono: "'JetBrains Mono', monospace",
  },
  shape:   "rounded",   // sharp|edged|rounded|soft|pill
  density: "cozy",      // compact|cozy|spacious
  nav:     "bottom",    // bottom|pill|rail
  icons:   "line",      // line|solid
  brand: { name: "My Wallet", glyph: "◈" },
};

import { applyTheme } from "./theme-engine";
applyTheme(document.documentElement, myBrand.id);
What you never touch: the encrypted vault, session lifetime, WDK account derivation, signing, dApp approval semantics, RPC validation, or the message-passing bridge. Theming is presentation-only — by design.
Guardrails baked in. Confirmation screens always lead with decoded action details, origin, amount, and warnings. No theme can blur, truncate, or hide approval-critical data — the contract has no token for that.
